Floorplan Retargeting：die 收缩下的宏布局迁移

Track B 候选题，工业界口径的重新定义。"用户已经有一版满意的宏布局，后来 die 要缩小，希望宏保持相对位置和大致分布"，在工业流程里对应的是 floorplan retargeting / floorplan migration：一份既有 floorplan 里沉淀了大量设计意图（相对位置、贴边、阵列、通道、电源网格与引脚关系），外框变了，意图要保住。下面先说工业界把它当什么问题、怎么解，再给出我们的正式定义，最后是交互演示，可在合成案例 synth_ring（117 宏、17 组、边界堆满一圈、多组向内堆叠）和 bp_fe、bp_be、bp_multi、swerv、ariane133（132 宏）五个专家布局之间切换。

一、工业界里这是什么问题

场景发生了什么为什么不能重新布出处
成本导向的衍生芯片 / 最小可行 die 探索同一工艺节点，砍功能或提高利用率后把 die 缩小以降低单颗成本；工具"自动分析约束、找出最小可布线 die 尺寸"，把 I/O 单元按比例重新塞进缩小后的边界，同时"保持原来的边、相对顺序和对齐"。pad ring、bump、封装已定；宏布局是时序收敛和电源网格的基础。Synopsys 专利 US 8037442
层次化 SoC 的分区重预算"某个 block 需要比预算略多的面积，芯片架构师就得改动周围 block 的位置"，连带电源环、JTAG、pin 都要重调；一次迭代 6 小时。每次 floorplan 变动都要重做 PG/时钟预布线，人工返工是主要成本。Design-Reuse《Dynamic Floorplanning》；Design-Reuse《Floorplan Guidelines》
跨节点迁移时的非均匀缩放逻辑缩 0.5×，SRAM 只缩 0.7 到 0.8×，模拟/PHY 几乎不缩；等价于"外框相对宏变小"。深亚微米下"shrink 几乎不可行，必须做非线性 relayout"。硬 IP 是固定 GDS，尺寸、形状、内部布线都不能改。SemiEngineering《SRAM Scaling Issues》；Design-Reuse《Hard IP》；TSMC 分区缩放专利 US 10685161
硬 IP / 模拟版图的 retargeting以旧版图为输入，用约束图模板保住"设计者的物理智慧"（对称、匹配、拓扑），再在新规则/新面积下求解。重新布局会丢失匹配与对称等隐性意图。Analog Layout Retargeting（Springer）；SMT-based retargeting（2025）

四个场景的共同内核：输入是一份带意图的 floorplan，输出外框变了，宏尺寸不变（或按各自因子缩放），要在新外框里给出合法布局，并尽量少破坏原意图。这正是用户描述的 macro shrinking。

二、工业界怎么解

1. 相对 floorplan 约束（EDA 工具内建）

Cadence Innovus 的 create_relative_floorplan：宏相对参考对象（core 边界、其他宏、group）以偏移量定位，"参考对象移动，宏跟着移动"，明确面向"层次化与衍生设计"。Design-Reuse 的 Dynamic Floorplanning 用 {参考点, 象限} + 偏移描述每个宏，用 reshape / relativereshape / reshapebetween 描述软块尺寸，"顶层 floorplan 按约束的重要性顺序手写"，尺寸变化后重放脚本即可再生，一次迭代从 6 小时降到 10 分钟。

2. 约束图压缩 + 留白按比例再分配

把布局转成水平/垂直约束图（sequence pair 的等价物），最长路径给出最小外框；若新外框放得下，把松弛量按原始通道宽度的比例分回去。IBM 的留白再分配专利给出公式：新弧长 = 原弧长 × 最小路径松弛 / 最大路径权重。这就是"保持大致分布"的精确版本。

3. 约束驱动的 floorplan 修复（FLOORIST）

把每对宏的关系写成 L/R/A/B 四选一的"松弛约束图"，只改造成冲突的宏（沿关键路径找 culprits），支持固定外框、区域、邻近、对齐约束；论文原话："The original solution should be preserved as much as possible"，评价用重叠率、HPWL、位移。

4. 现代 floorplanning 的约束分类

Young/Chu 与 Chen/Chang 的体系：preplaced、range、boundary、alignment、abutment、clustering、fixed-outline、rectilinear；fixed-outline floorplanning（Adya–Markov）是"给定外框内重排"的标准问题。

5. 阵列规整性（2026）

MacroAgent 把宏合法化的目标写成位移 + 规整性，规整性指数 R = Cmin/Cactual（理想方阵的通道数 / 实际通道数）；同尺寸宏先聚类、再按模板网格匹配。这给"bank 阵列不能被打散"提供了可计算的指标。

三、正式定义（我们的题）

Floorplan Retargeting under Outline Reduction。给定参考 floorplan F0：core 外框 O0，宏集合 M（尺寸固定）及其位置、朝向、halo，边界 IO 引脚；网表（宏–宏、宏–逻辑簇、宏–IO 连接）；目标外框 O1 = (sxW0, syH0)，s ≤ 1，允许 sx ≠ sy；物理规则 R：halo、最小通道宽度 cmin（电源条与信号布线）、site/track 对齐、允许的朝向操作（镜像）。求 O1 内每个宏的位置与朝向。

硬约束：宏两两不重叠（含 halo）、在 core 内、对齐 site；相邻宏之间及宏到边界的通道 ≥ cmin；IO 引脚按 die 缩放规则移动（同边、同序）。

意图约束 C(F0)，由 F0 自动提取，就是工业界用相对约束脚本手写的那套东西，这里改成机器抽取：

  • 相对关系：每对宏的 L/R/A/B 关系（约束图的传递约简 = 邻居关系），按连接权重加权。
  • 贴边与角落：距 core 边 ≤ halo+ε 的宏保持贴同一条边；角落宏保持角落。
  • 阵列与分组：同尺寸、行列对齐、等间距的宏集合（bank 阵列）保持成组、对齐、等间距；允许重折（2×4 → 4×2）但不允许拆散。
  • 引脚朝向：引脚面朝向原来的方向（朝向其连接质心 / 朝向核心内部）。
  • 通道结构：邻居之间与到边界的留白宽度向量 g0，目标是 g1 ∝ g0（在 cmin 之上按比例分配）。
  • IO 锚定：与边界 IO 强连接的宏保持在同一边附近。

专家优先级（冲突时怎么让步，来自"按重要性顺序写约束"的工业习惯）：合法性 > 通道/PG 可行 > 贴边与 IO 锚定 > 阵列完整 > 相对关系 > 留白比例。Hard 档就是故意让这些约束互相冲突。

隐藏参考 F1*：用"约束图压缩 + 按比例留白分配 + 必要时按优先级让步"的专家求解器生成，再用固定后端流程（复用 Track C 的 tc_flow：floorplan → 全局布局 → GRT 探针 + STA）验证可布线、时序不劣化；同 Track C，参考是"存在一条好解"的证明，不要求 agent 复现它。

五、参考解生成算法（fr_retarget，保证参考合法且符合专家标准）

参考解必须满足的专家标准

  • 合法：无重叠、在核心内、坐标对齐 site/row 网格（0.19 / 1.4 µm）。
  • 通道：非贴合的宏之间、宏与核心边之间，间隙要么是阵列内部贴合（≤ 2.5 µm），要么 ≥ cmin = 10 µm（电源条与信号布线）；不允许标准单元窄条。
  • 意图：组间 L/R/A/B 关系、贴边与角落、阵列（同尺寸等间距）保持成阵列、贴边宏引脚朝内、通道宽度按比例分配。
  • 让步顺序（放不下时的"微调"，每一步都记录）：阵列重折 → 不规则同类组重排成阵列 → 关键路径上的关系翻转（必要时放弃贴边）→ 两个对齐的同尺寸块并拢成一组。不同组之间永远不产生小于 cmin 的通道。
  • 不可行判定：让步用尽仍放不下则拒绝该缩比，case 生成器换更温和的目标。

步骤

  • 意图提取：同尺寸、对齐、相近的宏并成刚性块（同类 30 µm 内，异类仅贴合时）；包住外来宏的块拆成行/列段；完整网格记 (行, 列, 间距)；贴边 = 距核心边 ≤ 0.6 µm。
  • 松弛约束图（FLOORIST）：每对块一个关系，斜对角取归一化间距大的轴；H/V 图传递约简 = 通道。
  • 可行性：逐轴最长路径（边权 = 尺寸 + cmin，贴边边缘通道为 0）与目标外框比较。
  • 让步搜索：关键路径上生成候选动作，按"超出量减少 / 意图代价"排序（重折 1 + 长宽比变化 + 每个空位 1；重排 +1；翻转 3；放弃贴边 +4；并拢 5），分支限界，beam 3、2000 节点，取最便宜的可行序列。
  • 定位 LP（HiGHS，逐轴）：约束图差分约束 + 贴边等式 + 边缘留白；目标 = 每条通道相对 max(cmin, s·g0) 的相对偏差的凸分段线性罚（超过 20% / 50% 后斜率 2 / 4）+ 小权重的仿射目标位移。这是 IBM 留白再分配规则的 LP 形式。最后对齐网格、贴边宏引脚转向内侧。
  • 校验与度量：按上面的标准检查；输出组间关系保持率、贴边保持、通道偏差、位移。真实设计的后端验证交给 case 生成器（tc_flow 探针）。
